# PKG11 평가 프로토콜 (사전 고정)

2026-11-15 작성. 입력 고정 비교를 실행하는 도중, **결과를 보기 전에** 고정한 기준입니다. 근거는 GPT PKG11 검토 2.2·2.3입니다. 예산 한도는 사용자가 $60으로 올렸습니다(작성 시점 누적 약 $48.7).

## 구성

- **공통 보정(두 구성 모두):**
  - 지정 전제를 '지정 관련 구절' 인용으로 표시(긍정 조건으로 강화하지 않음)
  - 외부 법령 표시를 원문 참조 구간 인용으로 변경
  - 지정 표현 누락 2건 보완
  - note 누적
  - PKG10 검토 반영 2건
- **비교 대상(A):** `pkg_render_external_note`. 외부 법령 '목록' 참조 명제에 `외부 법령 참조: «구간» (이 조각은 그 목록을 직접 열거하지 않음)` note를 붙여 생성·검토·교정에 전달합니다.
- **범위 밖:**
  - 외부 정의(DEFINITION)와 위임은 note를 붙이지 않음
  - 외부 정의 추출 확대, 결정적 외부 목록 검사(B), 준용 표시(C)는 하지 않음

## 1단계: 입력 고정 비교 (전달 효과)

- **고정하는 것:** 질문 분해와 근거 선택은 PKG10 trace를 그대로 씁니다. 질의 임베딩은 PKG10 캐시를 씁니다.
- **새로 부르는 것:** 생성·검토·교정만 새로 호출합니다.
- **대상:** note가 실제로 붙는 문항 전부(449의 70, 증강 100의 16). note를 끈 상태의 생성 입력은 PKG10과 443/443 같으므로, 노출되지 않은 문항은 차이 0으로 둡니다.
- **표본:** 구성마다 1회. PKG10 저장 응답은 'note 없음' 기존 표본으로 함께 보고합니다.
- **보고:** 문항 짝을 유지한 주지표 차이(전체 세트 크기로 나눔), bootstrap 95% 구간, 오른 문항과 내린 문항 목록
- **판정 규칙**
  - note 있음 − note 없음의 구간이 0을 넘어 양수이면 '개선'으로 보고, PKG11 기본값을 켭니다.
  - 구간이 0을 포함하면 **판정 보류**로 보고, 기본값은 끕니다. 효과가 확인되지 않은 정책을 더하지 않습니다.
  - 구간이 음수이면 '악화'로 보고, 기본값은 끕니다.
  - 함정 응답을 따로 가중하지 않습니다. 주지표는 원본 check.py 문항 점수 평균입니다.
- **같은 입력의 표본 변동:** note 없음 새 표본과 PKG10 저장 응답의 차이로 함께 보고합니다.

## 2단계: 전체 파이프라인 1회 (공통 보정 + 1단계로 정한 기본값)

- **대상:** 449와 증강 100. 원질문부터 실행하고, check.py와 E2/E3를 돌립니다.
- **보고:** PKG10 대비 문항별 변화를 보고합니다. 반복이 1회뿐이라 버전 우열은 주장하지 않고, 구간이 0을 포함하면 판정 보류로 둡니다.
- **원문과 모순되는 표시나 전파가 재현되면** 성능과 관계없이 고칩니다.

## 예산과 종료

- **예상 비용:** 1단계 약 $0.5, 2단계 약 $6(생성 $1.65, 평가 약 $4.35). 합계 약 $55입니다.
- **반복 금지:** 결과가 불리해도 같은 비교를 다시 돌려 유리한 결과를 찾지 않습니다. 추가 반복은 사용자가 따로 정합니다.
- **사후 분석:** 프로토콜을 벗어난 분석은 사후 탐색으로 표시합니다.

## 추가: 후보 A~E 시험 (사용자 요청, 2026-11-15, 결과를 보기 전에 작성)

모든 시험은 1단계와 같은 **입력 고정** 방식입니다. 질문 분해와 근거 선택은 PKG10 trace를 쓰고, 생성·검토·교정만 새로 호출합니다. 각 구성은 설정 플래그 하나만 켭니다.

### 대조군과 표본

- **대조군:** note와 지적을 모두 끈 새 표본을 생성 단계까지 가는 모든 문항(449, 증강 100)에서 2회 뽑습니다(`ctl1`, `ctl2`).
- **같은 입력의 표본 변동:** `ctl2 − ctl1`로 보고합니다.
- **후보의 효과:** 각 후보 구성 − `ctl1`을 그 후보에 노출된 문항에서 짝지어 비교합니다. 노출은 플래그를 켰을 때 생성 입력(또는 B는 검토 지적)이 실제로 달라질 수 있는 문항입니다.

### 후보 정의

| 후보 | 플래그 | 내용 |
|---|---|---|
| A-지정 | `pkg_render_designation_note` | 지정 관련 명제에 `지정 관련 구절: «구절»` note. 긍정·제외·분기 판정이나 '지정 여부를 알 수 없음' 같은 문장은 붙이지 않음 |
| A-정의 | `pkg_render_definition_note` | 외부 정의 명제에 `외부 법령 참조: «구간»` note. 부재 단정 없음 |
| A-위임 | — | 시험하지 않음(과유보 위험, GPT 검토 2.1 동의) |
| B | `pkg_external_list_check` | 답한 요청의 주장이 외부 목록(LIST) 명제를 쓰면, 그 요청에 '핵심 미응답 확인 요청' 지적을 결정적으로 추가해 교정으로 보냄. 지적 문구: 목록 포함 여부에 기대는지 확인, 그 목록은 이 조각에 열거되지 않음. 교정자가 판단하며, 기권 수용은 기존 외부 의존 규칙(PKG8)을 그대로 씀. GPT 검토 4.2의 우려(태그만으로 핵심 미응답을 만듦)를 명시하고 시험함 |
| C | `pkg_render_junyong_note` | 내부 조문을 준용하는 명제에 `준용: «원문 준용 구절»` note. 분기·범위를 해석하지 않고 원문 구절만 인용 |
| D | — | PKG10 검토 반영분(이미 코드에 있음). PKG10 캐시를 전부 쓴 재생으로, PKG11 코드(입력 고정)가 PKG10 응답을 그대로 내는지 확인(비용 0) |
| E | — | 3표본 최종 판정 다수결: PKG10 기록, `ctl1`, `ctl2`. 다수가 답이면 고정 순서(PKG10, ctl1, ctl2)에서 첫 답변을 씀. 정답을 보지 않는 규칙. 비용·지연 증가(생성·검토·교정 3배)를 함께 보고 |

### 판정 규칙 (1단계와 같음)

- 차이의 95% bootstrap 구간(문항 재표집, 10,000회, seed 고정)이 0을 넘어 양수일 때만 '개선'으로 보고합니다.
- 구간이 0을 포함하면 판정 보류, 음수이면 악화로 보고합니다.
- 구간이 0을 넘어 양수인 후보가 있어도, 그 구성으로 전체 파이프라인을 다시 돌리는 일은 사용자 결정으로 남깁니다.
- 후보끼리 조합한 시험은 하지 않습니다.

### 예산

- 예상 비용: 대조군 2회 약 $1.7, 후보 4개 약 $0.7. 합계 약 $2.3입니다.
- 한도를 지키기 위해 각 실행에 예산 상한을 겁니다. 누적이 $59에 닿을 것 같으면 남은 시험(E 순)을 중단하고 미실행으로 보고합니다.
- 결과가 불리해도 다시 돌리지 않습니다.
