### F02 표의 행과 머리글 오분류 — 수정
- **원인:** 셀 첫머리에 숫자가 3자 이상 있는지로 데이터 행을 판별했습니다. "1. 위락시설 | 시설면적 67㎡당 1대" 같은 행이 머리글로 이어 붙었습니다. 또 표 뒤 `<비고>`는 표 밖이라는 이유로 명제가 되지 않았습니다.
- **수정:** [pkg_graph.py `segment_table`](../lawqa/pkg_graph.py:222).
  - 첫 행만 머리글로 봅니다. 데이터 행이 나오기 전에 첫 칸이 머리글 첫 칸과 같은 행(병합 셀 반복)만 다단 머리글로 잇습니다.
  - 목(가.) 행에는 앞 번호 행의 첫 칸을 문맥으로 붙입니다.
  - 표 사이 짧은 번호 제목(2. 휴양시설)은 소제목으로 머리글 앞에 둡니다.
  - 표 안팎의 비고는 번호 항목별 NOTE 명제로 둡니다.
- **전후:**

| 별표 | 수정 전 | 수정 후 |
|---|---|---|
| 주차장 별표2 | 행 1개, 머리글 1,048자, 비고 없음 | 행 11개, 비고 11개 |
| 주차장 별표3 | 3,692자 통째 1개 | 행 8개, 비고 13개 |
| 주차장 별표4 | 비고 1개(행 없음) | 행 2개, 비고 1개 |
| 도시공원 별표3·5·6 | 각각 통째 1개 | 행 8·3·10개 |
| 도시공원 별표2 | 행 32개(소제목 없음) | 행 32개(소제목 포함) |

  기존 정답에 쓰인 행·비고 id(주차장 별표1 행1~3·비고1~2, 별표4 비고1, 도시공원 별표2 행7·8)는 그대로입니다.

### F04 잘못 뽑은 정의어 — 수정
- **원인:** `"유실ㆍ유기동물(이하 "유기동물"이라 한다)"이란`처럼 따옴표가 중첩되면 `이라 한다)`가 용어로 뽑혔습니다.
- **수정:** [pkg_graph.py `definition_terms`](../lawqa/pkg_graph.py:396)가 괄호를 한 덩어리로 읽고, 본래 용어와 약칭을 모두 돌려줍니다(위 예: "유실ㆍ유기동물", "유기동물"). 정규식으로 찾은 정의 간선은 `required=False`(읽기 문맥)로 표시합니다. 인용 닫힘은 원래 정의 간선을 쓰지 않습니다.
- **전후:** basis가 `이라 한다)`인 정의 간선 7개 → 0개. 전체 정의 간선 247개는 모두 `required=False`입니다. 정의 용어 추출이 바뀐 명제는 이 1개뿐입니다.
- **남은 한계:** 본문 중간의 약칭 선언(「동물보호법」(이하 "법"이라 한다))은 정의 간선으로 만들지 않습니다.

### F05 요청 보존 — 부분 수정
- **수정:** [pkg_pipeline.py `request_wire`·`check_request_ids`](../lawqa/pkg_pipeline.py:40).
  - 계획 단계 요청에 R1… id를 붙여 선택·생성에 줍니다. schema의 요청 수를 그 개수로 고정합니다.
  - 출력 요청이 같은 수·같은 순서의 id(또는 같은 문구)가 아니면 계약 오류로 보고 복구를 1회 합니다. 최종 기록의 요청 문구는 모델이 다시 쓴 문구가 아니라 계획 단계 문구입니다.
  - 검토자에게 요청별 상태(ANSWERED/CORE_MISSING/SIDE_MISSING)와 주장을 함께 줍니다. 검토자는 요청 id(R2)로 `unanswered_core`를 지적할 수 있고, 이 지적은 버리지 않습니다.
- **수용하지 않은 부분:** 생성기의 SIDE_MISSING 상태는 유지합니다. PKG 1차→2차에서 과도한 분해로 생긴 부분 기권(정답 6, 함정 2)을 줄인 근거가 있습니다. 대신 질문 분해 지시에서 배경 진술·중복 요청을 만들지 않게 했습니다(PKG3). 핵심 요청을 부수 사항으로 돌린 경우는 위 검토 지적으로 잡습니다.
- **검사:** 수·id 불일치 계약 오류, 요청 id 지적 보존(`test_review_can_flag_unanswered_request_by_id`).

### F07 동일 요청 — 부분 수정
- **수정:** [llm.py `call`](../lawqa/llm.py:173).
  - 요청 해시별 잠금으로 같은 요청이 동시에 오면 한 번만 유료 호출하고, 나머지는 그 캐시를 씁니다.
  - 기다리는 동안 앞선 동일 요청이 처리 불명으로 끝나면, 기다린 쪽은 다시 보내지 않고 `same_request_uncertain` 오류를 냅니다.
  - 캐시 임시 파일은 쓰기마다 고유 이름입니다.
- **검사:** 가짜 transport로 동시 3건 → 호출 1회, timeout 중 대기 → 재전송 0회(`SameRequest`).
- **수용하지 않은 부분:** 처리 불명 요청을 프로세스 재시작 뒤까지 영구 차단하지 않습니다. 사용자가 같은 질문을 다시 하면 서비스가 계속 실패하게 되기 때문입니다. 처리 불명 비용은 예산 원장에 남습니다.

### F08 벡터 갱신 검사 — 수정
- **수정:**
  - `vectors.json`에 모델, 입력 한도, 명제별 실제 임베딩 입력 해시(`input_sha256`)를 저장합니다. 실행기는 id·모델·입력 해시가 모두 같아야 불러옵니다([pkg_runtime.py](../lawqa/pkg_runtime.py:64)).

- **검사:** 같은 id에서 입력 해시 하나를 바꾸면 불러오기가 실패합니다.
