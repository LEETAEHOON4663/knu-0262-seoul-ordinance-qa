## 2. 수정

### 그래프 (`lawqa/pkg_graph.py`, 재빌드 `tools/build_pkg.py --archive-tag pkg4`)
- **F14·F13:** 참조 추출에만 쓰는 본문 `ref_text()`에서 `[…이동…]`·`[…종전…]` 이력과 `(이하 "…"이라 한다)` 약칭 선언을 뺍니다. 명제 원문은 그대로 보존합니다. 외부 법령 조문은 `external_refs`(법령명·약칭·조문)로 남깁니다.
  - **결과:** 삭제된 간선은 정확히 98개(F14 90 + F13 8)이고, 다른 간선은 그대로입니다.
  - **인용 재조립(저장된 사용 명제 ID로, 호출 없이):** R3-SYN-A-02는 [제28조]만, A83은 [제23조①, ②]만 남습니다.
- **F16:** 같은 조례 안의 "제A항부터 제B항까지"는 중간 항까지 참조합니다. 외부 법령 범위는 제외합니다. 청년 13④의 닫힘에 13②가 들어옵니다.
- **F17:** 다른 항의 "제N항에도 불구하고"는 원칙 → 제한 항으로 `LIMITED_BY` 간선을 둡니다(4쌍, 5간선).
  - 다른 항에 적용되는 계산 규칙은 원문을 대조해 주차장 7① → 7②(단수 미계산) 1건을 `CALCULATION`으로 연결했습니다(검토 표시 `AI_REVIEWED`).
  - 두 역할 모두 읽기(전달)용이며 인용 닫힘에는 넣지 않습니다. 양방향 전환이나 같은 조 전체 연결은 하지 않았습니다.
- **F18:** 정의 양태와 용어 추출이 `"X"라 함은`도 인식합니다. 보관소를 쓰는 5개 항에 정의 간선이 생깁니다.
- **F19:** 표 셀의 항목 번호와 법령 참조 셀은 값에서 뺍니다(`cell_refs`로 보존). 준용·공고 셀만 있는 행은 `DELEGATED`(EXTERNAL_LAW / OTHER_ORDINANCE)로 둡니다. 카드에는 "값:위임"으로 표시됩니다.
- 검색 표현은 바뀌지 않아 벡터 1,099개를 모두 재사용했습니다(입력 해시 대조, 추가 비용 0).

### 생성·검토 계약 (`lawqa/pkg_prompts.py`, `lawqa/pkg_pipeline.py`) — F15
- **생성:** 요청마다 출력 순서를 `b_asked`(질문이 요구하는 바로 그 값·판정, 한정어 포함) → `c_basis`(원문이 그것을 DIRECT / APPLIED / SILENT / DELEGATED / EXTERNAL 중 무엇으로 주는지) → 주장 → 상태로 바꿨습니다.
  - "누가 정하나·누가 내나"는 위임·부담 조항이 DIRECT입니다. 그래서 위임 태그만으로 기권하지 않습니다.
  - 모델이 원문 지위를 SILENT·DELEGATED·EXTERNAL로 판정하고도 ANSWERED를 내면, 파서가 그 요청을 핵심 근거 부족으로 처리합니다. 판정 필드끼리의 일관성 검사이며, 답변 문장을 정규식으로 읽는 것이 아닙니다.
- PKG3의 "결론을 흐리지 말라" 문단은 제거했습니다. 경계값(이상·이하·이내), 전제 인용, 질문 분해 개선은 유지합니다.
- **질문 분해:** 질문의 한정어(지역·법규 이름·대상·기간·수량)를 요청에 남깁니다(T2의 '강남구 규칙' 누락 대응).
- **검토:** 자유 메모(`a_check`)를 요청별 구조화 판정으로 바꿨습니다. 각 요청에 대해 `a_request`, `b_check`, `c_verdict`(ANSWERED / UNANSWERED_CORE / SIDE)를 냅니다.
  - 판정이 UNANSWERED_CORE인데 조치 목록에 그 요청 지적이 없으면, 판정을 `unanswered_core` 지적으로 옮겨 교정에 넘깁니다(U082형 불일치 해소).
- **F01 교정 기권:** 다음 두 조건이 모두 맞을 때만 받습니다.
  1. 검토가 그 요청의 핵심 미응답을 지적했다.
  2. 교정자가 원문과 대조해 그 요청을 SILENT·DELEGATED·EXTERNAL과 CORE_MISSING으로 판정했다.

  다른 종류의 지적(조건 누락 등)에서 나온 기권은 계속 버립니다.

### O1 검토 미완료
- **원인:** 위 진단대로 제공자 쪽 Mini4 지연입니다. 시간 상한을 늘리거나 재호출하는 대신, PKG5 실행 설정에서 검토 모델을 Pro4로 바꿨습니다(`runs/FULL449/live_pkg5.json`의 `review_model`; 코드 기본값은 그대로). 요청별 판정이 추가돼 검토 출력 한도는 800→1,200토큰입니다.
- `/health`에 `verification` 집계를 추가했습니다. 검토 완료·미완료·생략 수와 "완료된 검토 없이 제출한 답변 수"를 HTTP 성공과 따로 셉니다.
- **12문항 점검:** 검토 12/12 완료, 시간 초과 0, 응답 3~12초.

### 검사
오프라인 검사 117개 → **123개 통과**. 추가한 검사는 다음과 같습니다.
