# PKG12 시험 프로토콜 (외부 의존 확인)

2026-11-16. 결과를 보기 전에 고정했습니다. 아이디어는 97.64% 제안([REVIEW_PKG10_9764.md](REVIEW_PKG10_9764.md))에서 가져왔고, 코드와 프롬프트는 가져오지 않았습니다.

## 변경

- **플래그:** `pkg_external_dependency_check`, 기본값은 끔입니다.
- **위치:** 교정이 끝나 최종 답이 정해진 뒤, 인용을 조립하기 전입니다.
- **검사 대상(게이트):** 최종 ANSWERED 요청의 주장이 쓴 명제 중 하나라도 그래프 속성상 조례 밖에 내용을 맡긴 경우만 검사합니다.
  - 외부 법령 참조(`external`: LIST, DEFINITION)
  - 위임(`delegation.to`가 NONE이 아님)
  - 게이트는 기존 그래프 속성 그대로이고, 이번에 새로 만들지 않았습니다.
- **판정 순서:**
  1. **점검 호출(답변을 봄):** 요청마다 결론이 조례 밖 내용에 달렸는데 답변이 단정했는지 판단합니다. 질문 인용, 답변 인용, 기대는 조각, 빠진 내용, 판정을 적습니다.
  2. **코드 검증:** 다음을 모두 만족할 때만 다음 단계로 갑니다.
     - 두 인용이 원문과 같습니다(공백 무시).
     - 가리킨 조각이 게이트에 걸린 조각입니다.
     - 빠진 내용이 비어 있지 않습니다.
  3. **반대 확인(답변을 보지 않음):** 그 결론을 전달된 원문만으로 정할 수 있는지 따로 판단합니다.
  4. **기권:** 반대 확인이 "핵심(CORE)이고 조례 밖 내용 필요(OUTSIDE)"라고 할 때만 답 전체를 기권으로 바꿉니다.
  - 호출 오류, 계약 오류, 시간 부족이면 답을 유지합니다.
- **모델:** 검토 모델(Pro4)을 씁니다. 449·증강 100 문항의 문장은 프롬프트에 넣지 않습니다.

## 시험

- **방법:** PKG11의 저장된 최종 답(449, 증강 100)에 검사만 사후 적용합니다.
  - 생성은 다시 하지 않으므로, 차이는 이 검사에서만 생깁니다.
  - 근거 원문은 trace의 선택 결과로 다시 전달·렌더링하고, 원래 전달 단위와 같은지 확인합니다.
- **대상:** 게이트에 걸리는 문항은 449에서 24개(정답이 기권인 문항 3개 포함), 증강 100에서 1개입니다. 이 수는 실행 전에 셌습니다.
- **반복:** 3표본입니다. 표본마다 새 캐시를 쓰고 따로 호출합니다.
- **지표:**
  - 표본별로 기권으로 바뀐 문항의 정답 기권(이득)과 정답 있음(손해) 수를 셉니다.
  - check.py 주지표 차이와 짝지은 bootstrap 95% 구간(10,000회, seed 20261116)을 냅니다.

- 프롬프트는 이 시험 전에 고정하고, 결과를 보고 고치지 않습니다. 고친다면 고친 판은 HOLD150에서만 평가합니다.

## PKG12b 449 개발 측정 (사용자 요청, 2026-11-16, 실행 전 기록)

- **추가 이유:** 사용자 요청으로 PKG12b도 449·증강 100에 3표본 사후 적용합니다.
- **하드코딩 아님:** 두 수정에는 문항 ID나 특정 문항의 단어가 없습니다. 질문 분해 인용 사용과 그래프 속성 기준의 대상 축소라는 일반 규칙입니다.
- **결과 해석 주의:**
  - 두 수정은 449의 G-07·G-10(인용 검증 실패)과 A74(내부 위임 오판)를 보고 만들었습니다.
  - A74는 대상 축소로 검사 대상에서 빠지므로, 이 문항의 손해는 구조상 다시 나올 수 없습니다.
  - 그래서 이 측정은 "수정이 의도대로 작동하는지" 확인하는 개발 측정입니다. 처음 보는 질문에서의 확인은 아닙니다.
- **기록 방식:** 판정 기준은 위 표를 그대로 적용해 기록합니다. HOLD150 평가 계획은 그대로 유지합니다.
- **비용 상한:** $0.10

## PKG12b 평가 (HOLD150, 2026-11-16 고정)

PKG12 첫 판의 449 결과(판정 보류)를 보고 고친 판입니다([PKG12_CHANGES.md](PKG12_CHANGES.md)). 그래서 449와 증강 100으로는 평가하지 않습니다.

1. **기준선:** HOLD150 기계 검사를 통과하면 PKG11을 코드 수정 없이 1회 실행하고 check.py로 채점합니다. 이 결과를 그대로 기록합니다.
2. **사후 적용:** 그 PKG11 답에 PKG12b를 사후 적용해 3표본을 돌립니다. 생성을 다시 하지 않으므로 차이는 이 검사에서만 생깁니다.
3. **판정 기준:** 위 표와 같습니다(이득은 정답 기권을 맞게 기권, 손해는 정답 있는 문항을 기권).
   - 채택 후보는 3표본 모두 손해 0, 이득 1 이상
   - 기각은 어느 표본이든 손해가 이득보다 많거나 손해 2 이상
   - 그 밖은 판정 보류
4. **채택:** 채택 후보이면 PKG12b를 기본값 켬으로 바꿉니다. 이후 HOLD150도 개발 자료로 분류합니다.
5. **비용 상한:**
   - PKG11 생성 $0.60(예상 약 $0.45)
   - 사후 적용 3표본 $0.15
   - check.py 채점은 무료입니다.
   - E2/E3 평가는 남은 예산을 보고 따로 정합니다.

## PKG12 완성판 시험 (2026-11-16, 실행 전 고정)

사용자 요청으로 97.64% 제안의 복구 단계 논리를 참고해 PKG12를 완성하고 449·증강 100에서 시험합니다. 제안 코드와 프롬프트는 쓰지 않습니다. 449·증강 100은 개발 자료이므로, 이 시험은 개발 측정입니다. 최종 확인은 HOLD150에서 합니다.

### 구성 요소(각각 플래그, 모두 일반 규칙)

| 요소 | 플래그 | 작동 |
|---|---|---|
| A. 외부 의존 확인 | `pkg_external_dependency_check` | PKG12b 그대로입니다. 답의 주장이 쓴 명제가 외부 법령 참조·위임일 때 점검하고 반대 확인합니다. |
| B. 용어 정의 확장 | `pkg_extdep_imported_terms` | 질문에 외부 법령으로 정의된 용어의 하위 종류(그 용어로 끝나는 더 긴 낱말이면서 그 조례가 따로 정의하지 않은 낱말)가 있고, 답이 같은 조례를 근거로 쓰면, 그 정의 명제도 A의 검사 대상에 넣습니다. |
| C. 기권 복구 | `pkg_abstention_recovery` | 생성이나 교정에서 핵심 요청 근거 부족으로 기권한 답에 적용합니다. 아래 다섯 단계를 모두 통과할 때만 답으로 되돌립니다. |

C의 다섯 단계는 다음과 같습니다.

1. **위치 확인(초안을 보지 않음):** 요청마다 결론을 직접 정하는 조각과 원문 구절을 찾습니다.
2. **코드 검증:** 조각이 전달된 원문에 있고, 구절이 그 조각과 글자 그대로 같고, 판정이 DECIDES여야 합니다.
3. **재생성:** 위치 확인 결과를 주고 다시 생성합니다. ANSWER가 나와야 하고, 복구한 요청의 주장이 확인된 조각을 근거로 써야 합니다.
4. **검토:** 지적이 하나도 없어야 합니다.
5. **외부 의존 확인(A):** 기권 판정이 나오지 않아야 합니다.

선택 단계에서 근거 0개로 기권한 경우(전달된 원문 없음)는 C의 대상이 아닙니다.

### 실행 전에 센 대상 수(PKG11 trace 기준)

- **A:** 449 12, 증강 0
- **B로 더해지는 문항:** 449 6, 증강은 실행 때 셉니다.
- **C:** 449 56(정답 있는 문항 5개 포함), 증강 1
- A는 PKG12b 3표본 결과(판정 보류)를 이미 알고 있습니다.

### 방법

- PKG11 저장 결과에 사후 적용합니다.
  - 답한 문항에는 A+B를 적용합니다.
  - 생성 단계에서 기권한 문항에는 C를 적용합니다.
- 표본은 3개이고, 표본마다 새 캐시를 씁니다.
- C의 재생성·검토는 PKG11 설정(생성 Pro4, 검토 Pro4)을 씁니다. 원문은 trace의 선택 결과로 다시 전달하고, 원래 전달 단위와 같은지 확인합니다.
- **통합 확인:** 실제 파이프라인을 플래그를 모두 켠 채 449 일부 문항으로 실행합니다. 문항은 각 경로가 한 번 이상 지나가도록 성질로 고르고, 결과는 판정에 쓰지 않습니다. 오류·지연·호출 흐름만 봅니다.

### 판정 기준

이득은 PKG11보다 점수가 오른 문항, 손해는 내린 문항입니다. 요소별(A, B, C)과 전체에 각각 적용합니다.

| 판정 | 조건 |
|---|---|
| 채택 후보 | 3표본 모두 손해 0, 이득 1 이상 |
| 순이득 확인 | 채택 후보는 아니지만, 3표본 모두 점수 순증이 0보다 크고 손해 1 이하 |
| 기각 | 어느 표본이든 손해 점수가 이득 점수보다 크거나, 손해 2 이상 |
| 판정 보류 | 그 밖 |

- 채택 후보나 순이득 확인인 요소는 PKG12 기본 구성에서 켜고, HOLD150에서 확인합니다.
- 기각인 요소는 끕니다.
- 판정 보류인 요소는 끄고 HOLD150에서 다시 봅니다.
- 이 시험 뒤에는 지시문과 게이트를 고치지 않습니다. 고치면 HOLD150에서만 평가합니다.
- **비용 상한:** 사후 적용 $0.80, 통합 확인 $0.10.
