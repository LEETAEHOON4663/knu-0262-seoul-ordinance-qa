## 교차검증을 요청하는 항목

### 1. [최우선] 속성 추출 정확도 — A가 전달할 정보가 맞는가

A는 추출된 속성을 생성·검토 입력에 그대로 올립니다. 추출이 틀리면 잘못된 note가 모델 판단을 왜곡합니다.

- **점검 대상:** `attrs_audit.json`의 명제 전부(외부 LIST 14, 외부 DEFINITION 7, 지정 전제 16, 위임 47)
- **점검할 것**
  - 오탐(속성이 붙었지만 원문상 아님)
  - 누락: 같은 패턴인데 속성이 없는 명제. 조례 원문 `data/corpus.json`과 `data/pkg/graph.json`을 직접 봐 주세요.
  - 외부 LIST의 범위: 성격이 다른 세 경우를 같은 note로 다뤄도 되는지
    - 도시공원 제20조 각 호: 감면 대상자의 범위가 외부 법령 목록에 있음
    - 제22조①: 금지 행위 목록이 외부 법령에 있음
    - 제24조: 위원회 심의 사항이 외부 법령에 있음
  - '따른다' 정의 외에 다른 표현 형태의 외부 정의 누락
- **원하는 결과:** 명제 id별 판정(맞음/오탐/불확실)과, 고쳐야 할 추출 규칙

### 2. A의 note 문구와 전달 범위

- **문구의 성격:** 각 note가 '사실 전달'로 읽히는지, 모델에게 사실상 기권 지시로 작용할지 판단해 주세요.
  - 특히 지정 전제 note의 둘째 문장("실제로 지정됐는지는 원문으로 알 수 없음")이 걸립니다. 정답 문항의 정당한 조건부 답변("지정된 금연구역이라면 과태료 10만원")까지 기권으로 바꿀 위험이 있습니다.
- **지정 전제의 포함 여부:** 함정에 답한 경우 5문항, 정당한 정답 답변 20문항에서 쓰였습니다. 포함, 제외, 문구 수정 중 어느 쪽이 맞는지 의견을 주세요.
- **외부 DEFINITION의 포함 여부:** 정답 답변 8문항에서 쓰였고 함정 답변에서는 0문항입니다. 정의 대상 용어가 질문의 쟁점이 아닌 경우가 대부분입니다. 포함하면 이득 없이 위험만 있는지 봐 주세요.
- **위임을 뺀 판단이 맞는지** 봐 주세요.
- **검토(review)에도 같은 note를 줄지:** 검토가 note를 근거로 '핵심 미응답' 지적을 늘리면, 교정 단계에서 과유보나 답변 변동이 생길 수 있습니다.
- **원하는 결과:** 속성별 포함 여부와 권장 문구, 생성·검토 각각에 줄지 여부

### 3. 통계 해석의 타당성

| 근거 속성 | 정답 답변 | 함정 답변 |

| 외부 LIST | 0문항 | 4문항 |
| 지정 전제 | 20문항 | 5문항 |

- **독립 표본이 적습니다.** 함정에 답한 문항은 서로 다른 문항으로 11개뿐이고, 비율(40.5%, 43.2%)은 5회 실행 합계라 같은 문항을 중복해서 셉니다.

- **원하는 결과:** 이 신호로 A를 정당화할 수 있는지, 아니면 '정보 누락 결함을 고친다'는 설계 근거만으로 정당화하고 효과 주장은 하지 말아야 하는지. 더 나은 분석 방법이 있으면 제안해 주세요.
