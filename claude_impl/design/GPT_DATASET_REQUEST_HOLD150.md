# 서울시 조례 Q&A 보류 평가셋 제작 요청 (HOLD150)

2026-11-15. 증강 100(portal100-candidate-v2)과 같은 방식으로 새 평가 문항 150개를 만들어 주세요.

## 목적

- 지금 시스템은 한 번도 개발에 쓰지 않은 질문에서 아직 측정되지 않았습니다.
  - 기존 449와 증강 100은 둘 다 개발 중에 보고 고친 자료입니다.
  - 그래서 그 점수(449 0.96, 증강 100 1.000)는 실제보다 높을 수 있습니다.
- 이 세트로 고정된 시스템을 **한 번만** 측정합니다. 측정 전에는 문항을 보고 시스템을 고치지 않습니다.
- 특정 시스템의 약점을 겨냥한 세트가 아니라, **기존 449와 같은 분포의 새 질문**이어야 합니다.
- 증강 100은 449보다 쉬웠습니다.

  | 세트 | 확인 불가 비율 | 필수 근거 2개 이상 |
  |---|---|---|
  | 449 | 33% | 21% |
  | 증강 100 | 17% | 4% |

  이번 세트는 449의 비율을 따릅니다.

## 구성 (150문항)

| 유형(`type`) | 문항 | 기준 |
|---|---|---|
| 단순 조회 | 30 | 한 조·항이나 별표에서 바로 답이 나옴 |
| 조건 판단 | 40 | 대상·조건·예외를 사안에 적용해 결론을 냄 |
| 여러 조항 결합 | 30 | 결론에 둘 이상의 조·항(또는 별표)이 필요함. gold 필수 그룹 2개 이상 |
| 근거 없음 | 50 | 정답이 "확인 불가" |

- **분야:** 6개 조례에서 각 25문항씩 뽑습니다. 분야 안에서도 유형 비율이 위와 비슷하게 맞춥니다.
- **별표:** 답변 가능 100문항 중 10~15문항은 별표가 필수 근거입니다. 별표는 여러 유형에 섞여 들어가도 됩니다.
- **결론의 방향:** 긍정 답만 있지 않게 합니다. "아니요"나 조건부 결론인 문항도 섞어 주세요.
- **문체:**
  - 약 절반은 상황을 설명하는 시민 말투, 나머지는 조례 용어를 쓴 직접 질문으로 씁니다. 길이도 섞어 주세요.
  - 조문 번호를 질문에 직접 쓰는 문항은 10개 이하로 합니다.
- **날짜:** 날짜에 따라 답이 바뀌는 질문(경과 규정 등)은 피합니다. 꼭 필요하면 기준일을 질문에 적습니다.
- **질문 문장:** 150문항의 질문 문장이 서로 모두 달라야 합니다. 평가기가 같은 문장을 허용하지 않습니다.

## 답변 가능 / 확인 불가 판정

증강 100의 규칙을 그대로 씁니다.

- **answer:** 고정 조례로 일반 명제의 참거짓이나 규정의 존재·조건을 판단할 수 있는 경우입니다.
- **abstain:** 질문의 핵심인 금액·절차·개별 사실이 자료에 없는 경우입니다.
  - `answer_key`는 정확히 `"확인 불가"`이고, `gold`는 `[]`입니다.

확인 불가 50문항은 하위 유형(`abstention_subtype`)으로 나눠 주세요. 채점에는 쓰지 않고 분석에만 씁니다.

| 하위 유형 | 문항 | 예 |
|---|---|---|
| `rule_exists_missing_core_detail` | 20 | 관련 조문은 있으나 질문이 묻는 값·기준이 조례에 없음 |
| `delegated_elsewhere` | 10 | 법률·시행규칙·고시·시장 결정에 맡겨져 조례에 값이 없음 |
| `local_or_operational_fact` | 10 | 자치구 조례, 특정 시설의 위치·운영시간·연락처, 현재 운영 현황 |
| `no_related_rule` | 10 | 6개 조례에 관련 규정이 없음 |

- **위임과의 경계:** 질문이 위임 사실 자체(누가 정하는지)를 물으면 answer입니다. 위임된 구체 값을 물으면 abstain입니다.
- **확인 불가 문항은 답할 수 있어 보여야 합니다.** 실제 조례 용어와 관련 조문의 주제를 쓰고, 핵심 값만 자료에 없도록 만듭니다. 다른 도시나 무관한 분야처럼 바로 티가 나는 질문은 `no_related_rule` 안에서도 줄여 주세요.

## gold 형식 (check.py 기준)

- **라벨:** `서울특별시 <조례 전체 이름> 제N조[의M] [제K항]`, `… 별표 N`, `… 별도 N` 중 하나입니다.
  - 호·목은 쓰지 않습니다. 채점기는 항까지만 봅니다.
  - 항이 있는 조문은 항까지, 항이 없는 조문은 조까지 씁니다.
- **배열 구조:** 바깥 배열은 필수 근거 그룹이고, 안쪽 배열은 허용 대안입니다.
  - 대안은 같은 내용을 똑같이 뒷받침하는 조문일 때만 넣습니다.
- **gold에 넣는 조문:** 결론을 내는 데 없으면 안 되는 조문만 넣습니다.
  - 정의·목적·적용 범위처럼 배경만 되는 조문은 결론에 꼭 필요할 때만 넣습니다.
- **확인 불가 문항:** gold는 `[]`입니다.

## 레코드 형식

증강 100의 `audit100.json` 형식을 기본으로, 아래 필드를 맞춰 주세요. 예시는 `schema_example.json`에 있습니다.

| 필드 | 내용 |
|---|---|
| `id` | `HOLD26-{P,A,B,G,Y,S}{01..25}`. P 주차장, A 동물보호, B 자전거, G 도시공원, Y 청년, S 금연 |
| `domain`, `type` | `type`은 위 네 유형 이름 그대로 |
| `answerability`, `abstention_subtype` | 답변 가능 문항은 `abstention_subtype: null` |
| `annex_required` | 별표·별도가 필수 근거이면 true |
| `question`, `gold`, `answer_key` | |
| `required_claims`, `optional_claims`, `forbidden_claims` | 내용 평가기(E2/E3)가 씁니다. 필수 주장은 결론과 그 조건을 빠짐없이 담아야 합니다. |
| `evidence` | `law`, `label`, `source_url`, `effective_date`, `quote`, `purpose`. `quote`는 `ordinances.json` 또는 별표 원문과 글자 그대로 같아야 합니다. 확인 불가 문항도 관련 조문이 있으면 넣습니다. |
| `features` | 분석용 태그. 해당하는 것만 넣습니다: `예외`, `정의`, `위임`, `별표`, `수치`, `부정 결론`, `여러 조건` |
| `novelty_note` | 기존 549문항 중 가장 가까운 문항과 무엇이 다른지 |

## 하지 말 것

- **기존 549문항을 바꿔 쓰지 않습니다.** 같은 조문을 다시 써도 되지만, 묻는 사실·조건이 달라야 하고 그 차이를 `novelty_note`에 적습니다.
- **외부 지식으로 정답을 쓰지 않습니다.** 외부 법률 지식, 포털의 최신 요금·운영 정보는 쓰지 않고 고정 자료만 씁니다.
- **모델 결과로 문항을 고르지 않습니다.** GPT를 포함해 어떤 모델이 맞히는지 틀리는지 보고 문항을 고르거나 빼지 않습니다. 난이도는 위 구성 기준으로만 맞춥니다.
- 우리 시스템의 결과와 오류 목록은 일부러 드리지 않습니다.

## 검토

- 작성자와 다른 에이전트가 150문항을 교차검토합니다. 증강 100과 같은 방식입니다.
- 검토 항목:
  - 답변 가능 여부
  - gold의 충분성과 과잉
  - `answer_key`·필수 주장의 정확성
  - `quote` 원문 일치
  - 기존 549문항과의 중복
- README에 사람·법률 전문가 검수가 아니라는 점을 적어 주세요.
