# 서울시 조례 명제 지식그래프 RAG — 수정 설계

PKG-v2 · 2026-11-12 · 설계 Codex / 구현·테스트 Claude

**고정된 여섯 조례를 명제로 정리하고, 명제를 직접 검색한 뒤 필수 근거를 연결해 답변한다.** 그래프는 사전에 원문을 읽어 구축한다. 이 문서는 구현 기준이며, 새 구성의 구현·성능 검증이 끝났다는 뜻은 아니다. Claude의 기존 설계와 코드는 보존한다.

사용자의 최신 지시에 따라 임의의 후보 개수·검색어 개수·호출 횟수·홉 수·문자 수·소량시험 문항 수를 설계 상한으로 두지 않는다. 실제 대회 90초, 모델 입력 한도, 기존 비용 한도는 지킨다. 세부 설정은 구현과 실측으로 정하고 비교 시 기록한다.

## 1 전체 흐름

```text
사전 준비
조례 원문·표 → 명제와 출처 구간 → 조건·예외·정의 등의 필수 연결
                         ↓
              명제 검색 표현·임베딩·색인

질문 처리
질문의 핵심 요청과 검색어 정리
  → 원질문·검색어로 명제 검색
  → Solar가 요청에 필요한 후보 선택
  → 그래프로 필수 원문 복원
  → Solar가 요청별 판단과 답변 작성
  → 근거 검토와 필요한 교정
  → 주장에 사용한 출처로 인용·JSON 조립
```

핵심 변경은 **② 임베딩, ③ 검색, ⑤ 판단, ⑥ 인용, ⑦ 답변 가능 여부**다. ①은 팀원의 본문·표 인식 결과를 받아 누락과 출처를 확인하고, ④ 검토와 ⑧ 연결은 이 흐름에 맞춘다.

그래프 DB나 범용 법규 실행 엔진은 필요하지 않다. 원문·명제·간선 파일과 이를 조회하는 코드로 구성한다.

## 2 조례를 어떻게 명제로 만드는가 — ①②

명제는 **독립된 법적 효과와 그 효과에 필요한 원문**이다. 주체, 행위·효과, 발동 조건, 의무 강도, 적용 예외가 달라지면 분리를 검토한다. 같은 제한을 긍정·부정으로 반복한 문장은 합치고, 계산·끝수·지시어 선행절은 해당 효과에 붙인다. 단서가 별도 효과를 정하면 별도 명제로 만들고 원칙과 연결한다.

각 명제에는 다음을 저장한다.

| 내용 | 보존할 정보 |
|---|---|
| 출처 | 명제 ID, 조례·조·항·호, 정확한 원문 구간, 원문 버전 |
| 효과 | 누가 누구에게 무엇을 의무·금지·허용·지원하는지 |
| 적용 | 조건·예외·정의·준용·계산 규칙과 각각의 원문 구간 |
| 값 | 무엇의 값인지, 숫자·단위·기간, 확정값·범위·산식 기준·외부 위임 등의 지위 |
| 불확실성 | 해석·추출·적용 범위가 미확정인 부분 |

각 호가 독립된 효과면 명제로 나눈다. 같은 효과의 대상 목록이면 공통 효과와 구성원을 연결하고, 구성원과 전체 목록 모두 검색할 수 있게 한다. 분리 기준이 애매하면 원문을 통째로 유지한다.

**표는 셀 값만 떼지 않는다.** 값과 행·열 헤더, 단위·기간, 주석, 연결 본문을 함께 보존한다. 한 행에 시간권·일일권·월정기권이 있으면 각각의 대응을 유지한다. 주석 셀의 병합 범위와 법적으로 적용되는 범위는 구분한다. 적용 범위가 미확정이면 주석 원문과 미확정 표시를 함께 전달한다.

모든 명제·속성은 원문으로 돌아갈 수 있어야 한다. LLM이 만든 요약을 법적 정본으로 삼지 않는다. 사람이 아닌 AI가 검토한 자료는 AI 검토로 표시한다. 정답세트·과거 점수를 명제 작성 입력에 넣지 않는다.

명제로 표현하지 못한 규정은 **원문 자체를 검색 가능하게 남긴다.** 일부 명제만 만들고 나머지 항 내용을 검색에서 사라지게 하지 않는다. 그림·별도 자료가 미검토라면 그 상태도 검색·생성·검토까지 유지한다.

## 3 그래프에는 무엇을 연결하는가 — ②③⑤⑥⑦

| 연결 | 의미와 사용 |
|---|---|
| 구조 | 조–항–호, 목록–구성원, 표–행. 위치와 전체 목록을 찾는 데 사용 |
| 필수 근거 | 공통 조건, 예외, 적용 정의, 준용, 계산, 경합 규정. 선택한 효과를 올바르게 읽기 위해 동반 |
| 표 문맥 | 헤더·단위·주석·본문의 요금 적용 규정. 표 값의 의미를 복원 |
| 외부 의존 | 규칙·고시·외부 법령에 맡긴 내용과 그 선언 원문. 외부 내용을 안다는 뜻은 아님 |

간선에는 연결 이유, 원문 근거, 적용 대상·범위, 검토 상태를 둔다. 단순히 관련 있다는 이유로 필수 간선을 만들지 않는다. 목록의 한 호가 선택됐다고 형제 호를 전부 필수화하지도 않는다.

선택 명제에서 **검토된 필수 연결을 따라 필요한 원문을 모두 복원**한다. 연결된 근거에 다시 필수 근거가 있으면 이어서 가져온다. 순환은 이미 방문한 ID로 처리한다. 초기 검색 후보 밖의 필수 근거도 원문 저장소에서 가져온다.

본문은 항 전체, 표는 헤더·주석이 완결된 영역을 기본 전달 단위로 한다. 항 전체를 보여 주면 그 안의 다른 규범도 답변에 쓰일 수 있으므로, 실제로 노출된 규범의 필수 의존도 복원한다. 같은 원문은 중복해서 넣지 않는다.

복원 결과가 지나치게 크면 먼저 잘못된 필수 연결·범위를 점검한다. 실제로 큰 묶음을 임의 개수나 글자 수로 잘라 완결된 근거처럼 보내지 않는다. 실제 모델 용량을 넘는 문제는 별도 처리 대상으로 기록한다.

등록된 연결을 모두 가져왔다는 것과 법적으로 필요한 연결을 빠짐없이 작성했다는 것은 다르다. 후자는 원문 검토로 확인한다.

## 4 무엇을 임베딩하고 어떻게 검색하는가 — ②③

**문서 쪽은 명제 단위로 임베딩한다.** 검색 문장은 제목, 효과의 원문, 적용 조건·예외·필요한 문맥을 코드가 조립한다. 표에는 헤더·단위·주석을 포함한다. 기존 항 벡터를 명제 ID에 붙여 명제 임베딩이라고 부르지 않는다. 실제 입력·모델·모드가 같은 성공 임베딩만 재사용한다.

질문에서는 핵심 요청과 검색에 유용한 표현을 정리한다. 일상 표현을 조례의 용어와 연결하되, 원질문 검색은 유지한다. 질문 배경이나 감정을 별도 법적 요구로 늘리지 않는다.

검색은 명제에 대한 임베딩 유사도와 BM25를 함께 사용한다. 순위 결합과 중복 제거를 적용한다. 동일 명제의 표현이 많다는 이유로 점수를 합산하거나 후보 자리를 여러 번 차지하지 않게 한다. 미표현 규정의 원문도 같은 검색 경로에서 찾는다.

Solar 선택기에는 후보의 제목만 주지 않고 **실제 효과·조건·예외가 보이는 근거 카드**를 준다. 원문과 법적 속성, 필수 연결을 확인하고 질문의 각 요청에 필요한 ID를 고르게 한다. 후보 수는 실제 입력 크기와 검색 누락을 확인하며 정한다. 특정 개수를 법적 충분성 기준으로 삼지 않는다.

선택 후 그래프의 필수 원문을 복원하고, 생성기에 원문과 관계의 역할을 전달한다. 카드 속성과 원문이 충돌하면 원문을 우선하고 자산 오류로 기록한다.

생성·검토·교정에서 **실제로 보여 준 원문과 사용할 수 있는 근거 ID 목록을 일치시킨다.** 같은 항의 다른 규정을 읽게 해놓고 그 규정을 인용할 ID는 숨기지 않는다. 문맥이 바뀌면 ID 목록·출처 대응도 함께 갱신한다.

## 5 판단과 답변 가능 여부 — ⑤⑦

질문의 핵심 요청마다 어떤 근거가 무엇을 답하는지 연결한다. 다음 구분이 중요하다.

- 법적 행위자와 수혜자는 다를 수 있다. “시장이 지원할 수 있다”는 규정에 시민이 “지원받을 수 있나”라고 물었다고 역할 불일치로 차단하지 않는다.
- 숫자가 있다는 것만으로 값 질문을 답한 것이 아니다. 요청한 금액·기간·규격과 근거의 값이 대응해야 한다.
- “지정된 장소에서”라는 질문 전제와 “현재 지정됐나”라는 사실 질문은 다르다.
- 외부 참조가 있어도 요청에 필요한 내용이 원문에 있으면 답할 수 있다. 핵심 값·사실이 외부에만 있으면 그 부재를 인정한다.
- 명시된 값·조건으로 잘못된 일반 명제를 반박할 수 있다. 지원된 부정 답변을 ‘확인 불가’로 바꾸지 않는다.

내부 판단은 **근거 있는 긍정·부정·조건부 답변 / 핵심 근거 부족**으로 구분한다. 이 구분은 문구 정규식이나 역할 태그 하나로 결정하지 않는다. “규정하지 않는다”라는 표현도 질문에 대한 반박인지, 필요한 정보가 없다는 뜻인지 문맥으로 본다.

후보에서 못 찾았다는 사실은 조례 전체에 규정이 없다는 증거가 아니다. 검색·선택 부족과 실제 자료 밖의 정보를 로그에서 구분하고, 전자는 오류 분석 때 원문으로 확인한다.

대회 제출에서는 핵심 요청을 근거로 답할 수 없을 때 아래 객체를 출력한다. 일부 관련 설명으로 핵심 미응답을 가리지 않는다.

```json
{"answer":"확인 불가","citation":[],"source_url":"","effective_date":""}
```

JSON 오류·시간초과·API 실패를 이 정상 기권으로 바꾸지 않는다.

## 6 검토와 인용·출력 — ④⑥⑧

답변기는 요청별 판단과 주장별 문장·근거 ID를 함께 반환한다. 최종 답변은 그 주장으로 구성한다. 근거 목록과 무관한 자유 답변이 따로 생기지 않게 한다.

Mini 검토는 요청 미응답, 근거 없는 주장, 조건·예외·양태·값의 오적용, 필요한 출처 누락을 본다. 문제가 있으면 Pro4가 원문으로 수정하거나 근거를 들어 지적을 기각한다. 검토 의견만으로 기권시키지 않는다. 불필요한 인정 판정·재검증 호출을 덧붙이지 않고, 실제 문제를 확인한 단계만 고친다.

검토에서 새로운 근거를 사용했다면 교정자에게도 그 **원문·ID·필수 연결**을 제공한다. 보지 못한 원문을 근거로 수정하라고 요청하지 않는다.

인용은 최종 주장에 쓰인 명제의 출처와 그 주장에 필요한 필수 근거로 조립한다. 읽은 모든 원문이나 선택된 모든 후보를 자동 인용하지 않는다. 넓게 읽기 위한 연결과 주장 지원을 위한 연결은 구분한다. 인용은 명제 ID가 아닌 정식 조·항·별표 라벨로 출력한다.

코드는 ID 존재 여부, 실제 전달 원문과의 대응, 요청 누락, 출처·시행일, 제출 JSON을 검사한다. 잘못된 ID를 조용히 지운 다음 기권 처리하지 않는다. 검토되지 않은 답변을 검토 통과로 기록하지 않는다.

성공한 동일 실제 요청은 캐시로 재사용하고, 처리 불명 요청은 재전송하지 않는다. 동시 요청의 중복 호출과 캐시 쓰기 충돌을 막는다. 새 원문·그래프·프롬프트를 과거 캐시와 혼용하지 않는다.

## 7 구현 확인과 성능 비교

먼저 설계가 연결됐는지 확인한다: 명제 원문 대응, 표 문맥, 미표현 원문 검색, 필수 연결 복원, 생성·검토·교정의 근거 전달, 주장별 인용, 오류와 정상 기권의 구분이다. 이 검사는 새 법률 평가셋을 만드는 작업이 아니다.

성능 비교는 다음 두 구성을 같은 문항·모델·검토·출력 정책으로 실행한다.

| 구성 | 검색과 근거 제공 |
|---|---|
| 기준선 | 기존 V8의 원문·검색 표현 |
| 변경안 | 명제 직접 검색·카드 선택·필수 그래프 복원 |

파서·캐시·교정 원문 전달 같은 공통 버그는 두 구성에 동일하게 고친다. 그래야 단순 오류 수리 효과와 명제 그래프 구성의 차이를 구분할 수 있다. 이 비교는 전체 구성의 효과이며, 그래프만의 단독 효과라고 부르지 않는다.

주지표는 **원본 check.py의 문항별 부분점수 평균**이다. 통과율이나 내용 정확도로 바꿔 부르지 않는다. 보조로 과유보·함정 비기권·운영 오류·지연·비용만 확인한다. 개선·악화 문항은 원문과 실행 경로를 대조한다. 생성·채점에 실패한 문항을 분모에서 빼지 않는다.

기존 승인 평가자료와 정답은 고정한다. 임의의 소량시험 문항 수나 성능 합격선을 추가하지 않는다. 구현 확인 후 승인된 범위와 남은 예산 안에서 비교하고, 실행하지 못한 범위는 공개한다. 기존 V8 점수와 과거 Q32 점수는 평가집합이 달라 직접 비교하지 않는다.

**실제 제약만 유지한다.** 대회 HTTP 90초, 모델의 실제 용량, 기존 누적 USD10 및 공유 원장의 USD9 예약 차단선이다. 내부 85초나 호출 6회 같은 별도 상한은 두지 않는다. 실행 중 남은 시간과 실제 비용을 관리하며 불필요한 호출을 줄인다. Claude 사용액과 공유 원장의 중복 여부를 확인하고, 기존 지출·불명 예약을 초기화하지 않는다.

## 구현 인계

Claude는 이 설계로 원문·명제·간선·검색·답변 연결을 구현하고 실제 작동을 확인한다. 세부 설정은 코드와 테스트 결과에 남긴다. 설계 변경이 필요하면 원인과 영향을 기록한다.

원본 설계·응답·실패 기록은 보존한다. 새 원시자료·벡터·응답은 기존 연구 서버에 둔다. 완료 보고는 설계 반영, 실제 작동 확인, 성능 비교를 구분한다. 이번 문서 수정 자체는 유료 실험이나 예약 재개를 실행하지 않는다.
