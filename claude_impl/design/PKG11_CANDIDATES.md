# PKG11 수정 후보 (근본 원인 분석, 2026-11-14)

목표는 특정 문항에 맞춘 수정이 아니라, 여러 문항과 여러 실행에 걸쳐 반복되는 **구조적 원인**을 찾는 것입니다.

- **자료:** PKG6~PKG10 다섯 번의 실행(449 + 증강 100, 응답·trace·E2/E3)
- **방법:** 모두 오프라인 재계산입니다. 새 비용은 seed 확인 호출 8건(약 $0.005)뿐입니다.
- **문항 id의 쓰임:** 증거 사례로만 적습니다. 어떤 후보도 특정 문항이나 조문을 조건으로 쓰지 않습니다.

> **검토·실측 후 정정 (2026-11-15).** 이 문서의 일부 해석은 GPT 교차검토([GPT_PKG11_REVIEW_RESPONSE.md](GPT_PKG11_REVIEW_RESPONSE.md))와 실측([PKG11_CHANGES.md](PKG11_CHANGES.md))으로 바뀌었습니다.
> - "실행 간 변동은 생성 단계 판정에서 온다"는 근거가 없었습니다. 같은 요청 비교에서 직접 보인 변동은 질문 분해 단계입니다.
> - "±0.005 잡음"은 작게 잡은 값이었습니다. 입력을 고정한 같은 구성 2회의 449 주지표 변동은 ±0.012(95%)입니다.
> - 후보 A의 초안 note 문구는 원문과 다른 정보를 담고 있어 고쳤습니다. 원문 구절 인용만 쓰고, 부재 단정은 없앴습니다.
> - 후보 A~E는 모두 판정 보류였습니다.

## 1. 손실 구조

449에서 PKG6~10 중 한 번이라도 틀린 문항은 50개입니다.

| 구분 | 문항 수 | 내용 |
|---|---|---|
| 5회 모두 틀림 | 15 | 과유보 4, 부분 인용 7, 함정 응답 4 |
| 1~4회만 틀림(실행마다 바뀜) | 35 | 틀린 경우 대부분이 **생성 단계의 원문 지위 판정**에서 갈림. 과유보 23회, 함정 응답 17회, 부분 인용 23회, 운영 오류 4회 |

- **질문 분해의 영향은 작습니다.** 실행마다 바뀌는 35문항 중 맞은 실행과 틀린 실행의 요청 수가 다른 경우는 5개뿐입니다.
- **내용 오류는 드뭅니다.** 다섯 번 실행에서 답한 정답 문항의 E2 미판정·오답은 10건이고, 그중 판정자가 실제로 지적한 것은 3건(A33, A26, A71)입니다. 손실의 대부분은 기권 판단과 인용 범위입니다.
- **E3 실패(PKG10 26건):** 인용 불완전 18건, E2 실패 14건입니다.
- **E3 미판정(64건):** 대부분 평가기 쪽 문제입니다. 판정자 인용문 계약 오류 46건, 시간 초과 11건입니다.

### 실행 간 변동의 원인: API 비결정성 (확인)

- **같은 요청, 다른 출력:** PKG9와 PKG10 캐시에서 요청 본문이 완전히 같은 호출 462건 중 **424건(92%)이 다른 출력**을 받았습니다(temperature 0).
- **seed 효과 없음:** 같은 질문 분해 요청을 seed 없이 4회, `seed: 7`로 4회 보냈습니다. 두 경우 모두 4회 출력이 전부 달랐습니다. seed는 받아들여지지만 효과가 없고, `system_fingerprint`도 오지 않습니다.
- **결론:** 같은 코드라도 1회 실행 점수에는 대략 ±0.005의 잡음이 있습니다. 문항 몇 개 차이로 버전 우열을 정할 수 없습니다.

## 2. 후보 (우선순위 순)

### A. 그래프 속성을 답변·검토 단계까지 전달 — 구조 결함

- **사실:**
  - 선택 카드에는 그래프 속성이 모두 나옵니다(`card()`): 외부법령의존(LIST/DEFINITION), 위임, 지정된 경우에만 효과, 값, 효력 만료, 적용 대상.
  - 생성·검토에 주는 원문 조각(`render()`)에는 효력 만료, 적용 대상, 보충 문구 세 가지만 note로 붙습니다.
  - 답이 맞는지 판단하는 단계가 그래프의 판단 근거를 보지 못합니다. PKG10 검토 2번(그림 미검토 상태 누락)과 같은 종류의 결함이며, 범위가 더 넓습니다.
- **함정 답변과의 관련(다섯 번 실행, 최종 주장에 쓴 근거 기준):**

| 근거 속성 | 정답 문항 답변 1,876건 (서로 다른 문항 383개) | 함정에 답한 37건 (서로 다른 문항 11개) |
|---|---|---|
| 외부 법령 '목록' 의존(LIST) | 0% (0문항) | **40.5%** (4문항) |
| 지정 전제("지정된 경우에만 효과") | 4.4% (20문항) | **43.2%** (5문항) |
| 외부 법령 '정의' 의존(DEFINITION) | 1.2% (8문항) | 0% (0문항) |
| 위임 | 5.9% (33문항) | 10.8% (2문항) |

비율은 5회 실행 합계라 같은 문항이 여러 번 셉니다. 독립 표본은 괄호 안의 문항 수이고, 함정 쪽은 11문항뿐입니다. 재현 스크립트는 [tools/pkg11_analysis.py](../tools/pkg11_analysis.py)이고, 출력은 [pkg11_review_pack/](pkg11_review_pack/)에 있습니다.

- **같이 고칠 추출 누락:** `"담배"란 「담배사업법」 제2조를 따른다`처럼 '~를 따른다'로 끝나는 정의가 외부 정의로 표시되지 않습니다. 그래프 전체에서 이 형태는 1건입니다. 전자담배 함정 답변(5회 모두)이 이 조항에 기댑니다.
- **수정안:**
  - `render()`에서 외부법령의존(종류와 그 법령 문구), 지정 전제를 조각 note로 전달합니다. 기존 note와 겹치면 덮어쓰지 않고 이어 붙입니다.
  - 새 기권 규칙은 만들지 않습니다. 사실만 전달하고, 판단은 기존 원문 지위 정의(EXTERNAL, "지정됐나"는 현장 사실)에 맡깁니다.
- **위험:** PKG5처럼 보수화해 과유보가 늘 수 있습니다. 지정 전제는 정답 문항 답변에서도 83회(다섯 번 실행 합계) 정당하게 쓰였습니다(조건부 답변). '위임' 표시는 과유보 쪽 위험이 커서 이번 범위에서 뺍니다.
- **검증:** 전체 재실행이 필요합니다. 함정 응답(현재 8)과 과유보(현재 6)의 변화를 함께 봅니다.

### B. 외부 목록 의존 결정적 검사 — 기존 계약을 집행

- **사실:** 원문 지위 정의는 이미 "판정이 외부 법령의 목록 내용에 달려 있으면 EXTERNAL"입니다. 그런데 외부 목록 조항(예: '법 제49조 각 호의 행위를 하여서는 아니된다')을 근거로 특정 행위의 금지 여부를 단정한 답이, 함정 응답 37건 중 15건입니다.
- **수정안:**
  - PKG9 범위 검사(F25)와 같은 방식입니다. 주장이 외부 LIST 의존 명제를 근거로 쓰면, '외부 목록 포함 여부에 기댄 결론'으로 교정에 지적합니다.
  - 교정이 EXTERNAL로 판정하면 기존 외부 의존 기권 규칙(PKG8)으로 받습니다. 이 규칙의 조건 중 '검토의 핵심 미응답 지적'에 이 결정적 지적도 포함합니다.
- **오탐:** 정답 문항 답변 1,876건 중 0건입니다.
- **한계(과적합 주의):** 그래프의 외부 LIST 명제는 14개(도시공원 제20조 각 호, 동물보호 정의 등)입니다. 그런데 관측된 함정 응답은 모두 도시공원 제22조① 하나를 거칩니다. 메커니즘은 일반적이지만 증거가 한 조항에 몰려 있습니다. A의 정보 전달만으로 충분한지 먼저 보고, B는 A의 실측 후 판단하기를 권합니다.

### C. 준용 관계를 타입 있는 관계로 표시

- **사실:** 내부 준용 조항 6개('제5조제2항과 제3항의 규정을 준용한다' 등)가 일반 참조(REFERENCE)로만 연결돼 있습니다. PKG10 A26은 준용을 놓쳐 결론이 틀렸습니다("해제에는 고시 의무 없음").
- **수정안:** 적용 대상 표시(F25 `applies_to`)의 반대 방향입니다. '준용: 이 조의 대상(지정 변경·해제)에 제5조②·③을 적용'을 note로 전달합니다.
- **평가:** 해당 조항이 적고 관측 오류도 1건이라 효과는 작습니다. 다만 위험도 작고 법적 구조를 그대로 옮기는 수정입니다.

### E. 실행 간 변동 줄이기 — 측정 후 결정

- **선택지:** 생성 단계 판정을 3회 표본의 다수결로 정합니다.
- **기대 효과(추정):** 비슷한 코드인 PKG8·9·10의 문항별 중앙값을 내면 0.9614로, 단일 실행 평균 0.9566보다 약 +0.005 높습니다. 버전이 섞인 근사치입니다.
- **비용:** 449 1회 생성비가 약 +$1.3 늘고 지연도 늘어납니다.
- **권장:** A~C보다 뒤에, 예산을 정하고 하는 선택 사항입니다.

## 4. 부분 인용의 실제 원인 (남는 문제)

다섯 번 실행의 부분 인용 61건에서 빠진 정답 조문이 어디서 빠졌는지 추적했습니다.

| 빠진 단계 | 건수 | 대표 문항 |
|---|---|---|
| 선택했고 전달됐지만 주장 근거 id에 없음 | 29 | X40-M09(정의 조항), U065, U016 |
| 카드에 있었지만 선택 안 됨 | 24 | 같은 조 제1항(사업 근거)을 빼고 세부 항만 고름: A-09, A-11, A-15, Y-07 |
| 필수 연결로 전달됐지만 주장에 안 씀 | 7 | P-06, Y-07 |
| 검색되지 않음 | 1 | |

- **결정적 규칙으로는 풀리지 않습니다.** 3절에서 본 것처럼 정밀도가 낮습니다.
- **남은 방향은 생성 지시입니다.** "주장이 기대는 대상·범위·정의·사업 근거를 정한 조각 id도 넣는다"는 지시를 넣는 것입니다. 기존 '전제 확인 id' 규칙을 넓히는 셈입니다.
- 모델 판단이 바뀌는 수정이라 전체 재실행으로만 확인할 수 있습니다. 넣는다면 A와 따로 비교할 수 있게 별도 실행이 필요합니다.

## 5. 과적합을 막는 평가 방식 (제안)

1. **후보와 채택 기준을 먼저 고정합니다.** 함정 응답, 과유보, 부분 인용이 각각 얼마나 움직이면 채택할지 실행 전에 정합니다.
2. **새 보류 세트를 둡니다.** 449와 증강 100은 모두 개발에 쓰였습니다. 새로 만든 질문 세트를 한 번도 보지 않은 채 최종 비교에만 씁니다.
3. **같은 코드를 2회 실행합니다.** 실행 간 잡음(약 ±0.005)을 재고, 그 폭보다 큰 차이만 개선으로 봅니다.
4. **수정은 하나씩 비교합니다.** 오른 문항과 내린 문항 목록을 함께 남깁니다.
