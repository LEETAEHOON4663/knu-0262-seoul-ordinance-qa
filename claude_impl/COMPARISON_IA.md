## 구조 차이

| 항목 | IA | 이 구현 |
|---|---|---|
| 검색 단위 | 트리 노드 1,272개(조·항·호·목·표행·비고). 상위 문맥을 붙인 텍스트로 임베딩 | 원문 525단위(항·별표)를 그대로 전달 |
| 초기 gate | dense+BM25 최고 코사인 0.25 미만이면 기권 | 없음(어휘가 전혀 겹치지 않을 때만 기권) |

## 반영한 것

1. **② dense 검색**: IA의 동결 노드 벡터(1,272×1024, sha 20d4ea…)를 읽기 전용으로 재사용합니다. 노드 인용 라벨을 우리 단위로 사상해 1,272개 모두 매핑됐고(미매핑 0), 단위 점수는 노드 코사인의 최댓값입니다. 재임베딩 비용은 없고, 질의 임베딩만 실행 중 1회 호출합니다.
2. **⑥ T1 인용 보충(결정적, 모델 호출 없음)**: 답변 문장에 쓴 같은 조례의 조·항·별표가 모델에 보낸 문맥 안에 있었는데 인용에서 빠졌으면 추가합니다. 외부 법령 조문은 제외하고, 여러 조례가 섞이면 하지 않습니다.
3. **⑦ 첫 문장 부정 규칙**: 답변 첫 문장이 "확인할 수 없다 / 조례에 규정이 없다"면 정형 기권합니다(IA `draft_ids` 정규식 두 개).
4. **③ 문맥 예산을 1.6만 자에서 1만 자로 축소**: 아래 진단에서 dense를 켜면 1만 자로도 정답 근거 포함률이 99.3%였습니다. 비용·지연과 모델 혼동이 줄어듭니다.

## 반영하지 않은 것

- **초기 0.25 gate**: 모델 판단 전 기권은 근거 있는 질문의 과유보 위험이 있습니다. 소량 실측에서 함정 문항 오답이 많으면 다시 검토합니다.
- **10개 선택 후 생성(선택·생성 분리)**: R9에서 선택 누락 사례가 있었습니다. 문맥이 1만 자라 한 호출로 충분하다고 판단했습니다.
- **재검증 루프, Mini4 정규화 호출**: 구조 판단과 첫 문장 규칙으로 대신합니다.
- **T3(미지원 부분이 배경인지 재검사)**: 요구 분해 지시에서 "전제·배경은 요구가 아니다"로 처리합니다. 실측에서 부분 지원으로 인한 과유보가 보이면 조건부 호출로 추가합니다.

## 오프라인 진단: 문맥 안 정답 근거 포함률

`tools/retrieval_recall.py`로 측정한 개발 자료 진단이며, 모델 점수가 아닙니다.
- 대상: 근거 있음 303문항. 질의계획 검색어는 없습니다.
- 질문 벡터: IA에 저장된 성공 응답만 재사용(67문항은 벡터가 없어 BM25만 사용)
- 지표: 모델이 문맥 안 근거를 완벽하게 인용한다고 가정한 인용 점수 상한
