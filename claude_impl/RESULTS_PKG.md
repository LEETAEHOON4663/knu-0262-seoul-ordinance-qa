  - 시험용 플래그(PKG11 후보, PKG12, W2, W3)는 모두 끔입니다.
  - W1 그래프 보완은 빌드 옵션(`tools/build_pkg.py --w1`)으로만 남겼습니다.
- **W1을 뺀 이유:**

## PKG 1차 → PKG2 수정 (449 결과를 보고 고친 항목, 분리 표시)

1. **① 명제 분할 버그:** "7의3." 같은 가지 번호 호가 별도 명제가 되지 않았습니다. 모델이 그 ID를 쓰면 없는 ID가 되어 운영 오류가 났습니다(3건). 7개 호를 분할하도록 고치고 그래프와 임베딩을 다시 만들었습니다.
2. **계약 과잉:** '핵심 근거 부족' 요청의 설명 문장에도 근거 ID를 요구해 계약 오류가 났습니다(4건). 기권하는 요청의 설명은 제출하지 않으므로 무시하도록 바꿨습니다. (건수 정정: 처음 보고에서 1·2의 건수가 뒤바뀌어 있었습니다. 실측은 없는 ID 3건, `claim_without_ids` 4건입니다.)
3. **교정 단계 기권 금지:** 교정이 답을 기권으로 바꾼 경우는 정답 8건, 함정 0건이었습니다. v2 원칙("검토 의견만으로 기권시키지 않는다")대로, 교정이 기권을 내면 초안을 유지합니다.
4. **부수 사항 구분(SIDE_MISSING):** 답변 단계의 부분 지원 기권은 정답 6건, 함정 2건이었습니다. 원인은 질문 분해가 배경·절차를 별도 요청으로 만든 것이었습니다. 답변기가 요청 상태를 답함 / 핵심 근거 부족 / 부수 사항 근거 부족으로 구분하고, 핵심 근거 부족일 때만 기권합니다.

2~4는 449 결과를 보고 고친 것입니다. 449는 개발 자료라 일반화 성능은 별도 증강 테스트로 확인해야 합니다.

## 구현 요약
- **그래프** `data/pkg/graph.json`(PKG2 당시): 명제 1,038개, 간선 1,153개. 원문 525단위가 모두 한 번 이상 명제에 포함되고, 본문 명제의 원문 구간 불일치는 0입니다. 이 검사는 단위 포함·구간 일치만 봅니다. 표 행이 올바르게 나뉘었는지는 보지 않으며, 실제로 별표 일부가 잘못 나뉘어 있었습니다(아래 PKG4 수정 F02·F03).
  - 명제 종류: 항 본문, 도입문, 호, 단서, 표 행, 비고, 그림.
  - 구조와 구간은 코드로 결정적으로 자릅니다.
  - 속성(주체·양태·값·위임·외부 의존·지정 전제·조건·예외)은 원문 규칙으로 뽑고, Pro4 초안과 대조해 위임과 외부 목록 오판을 고쳤습니다. AI 검토이며 사람 검수가 아닙니다.
- **간선:** 도입문, 단서, 명시 조문 참조, 정의 호, 별표, corpus 검토 간선. 전이적 닫힘 크기는 원문 단위 중앙값 2, 최대 45입니다.
- **검색:** 명제 단위 BM25 + Solar passage 임베딩(명제 1,038개, $0.004)을 RRF로 결합합니다. 후보 40개는 오프라인 진단(정답 근거 포함률 0.994)으로 정했습니다.
- **선택:** 근거 카드(원문, 도입문 ID, 속성)를 보고 요청별 ID를 고릅니다. 제공되지 않은 ID는 계약 오류로 처리하고 복구를 1회 합니다(조용히 지우지 않음).
- **답변:** 전달 원문(선택 명제의 원문 단위 + 필수 닫힘)을 명제 ID 조각으로 보여 주고, 요청별 주장(문장 + 근거 ID)과 상태를 받습니다. 최종 답변은 주장 문장으로 구성합니다.
- **인용:** 주장에 쓴 명제의 출처 + 그 명제의 참조·예외·표 필수 간선 출처.
- **검토·교정:** Mini4 검토(주장 번호 기준) → 지적이 있으면 Pro4 교정 1회(검토와 같은 원문 사용). 교정으로는 기권하지 않습니다.
- **오프라인 검사:** 109개 통과(PKG 전용 20개 포함).
