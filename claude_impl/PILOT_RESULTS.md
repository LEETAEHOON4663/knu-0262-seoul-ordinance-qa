- **해석 주의**: 20문항 부분 실행입니다. 449 전체 점수가 아니며, IA 0.935(IA 자체 449 실행)와 같은 조건의 비교도 아닙니다. 같은 설정을 다시 돌려도 문항당 결과가 달라질 수 있어 ±0.1 안팎의 차이는 잡음일 수 있습니다.

## 확인된 원인과 조치

1. **검색은 병목이 아닙니다.** 실패 문항의 정답 근거는 모두 모델 입력 안에 있었습니다(오프라인 진단 포함률 99.3%).
2. **필드 출력 순서.** Upstage strict schema는 속성을 이름순으로 출력합니다(`answer` → `evidence_ids` → `requests`). 그래서 모델이 판단(requests)보다 결론("확인 불가")을 먼저 썼습니다. 판단 필드가 앞에 오도록 `a_`/`b_` 접두어를 붙였습니다.
3. **순번 ID 오지정.** 모델이 E15, E18처럼 이웃 번호를 골라, 제18조 제2항을 골라야 할 때 제18조 제3항을 고르는 오류가 생겼습니다. 그러면 답변기는 맞는 근거가 없다며 기권합니다. ID를 조례 약칭과 조문 위치로 바꾼 V5부터 근거 있음 평균이 0.93까지 올랐고 계약 오류는 0건이 됐습니다.
4. **근거 ID 배열 반복 퇴화.** enum 배열에 "E2","E2",…가 반복돼 JSON이 깨졌습니다(IA도 겪은 문제). 근거 목록을 문자열로 받고 코드에서 검증하는 방식으로 바꿨습니다.

## 남은 약점: 근거 없음(함정) 문항

PILOT20의 함정 5문항에서 0.2~0.4입니다. 문의 상황은 조례가 직접 정하지 않는데, 모델이 관련 조문으로 추론해 답합니다. 실패 유형은 세 가지였습니다.
- 질문 주체가 조례에 없는 경우: 관리사무소를 묻는데 조례는 구청장만 정함
- 외부 법령 내용에 달린 경우: 드론 금지 여부가 도시공원법 제49조 각 호에 달림
- 원문에 없는 사실을 추정해야 하는 경우: 인터넷 선결제 가능 여부

Mini4 검토기는 함정 5건을 모두 지적했습니다. 그러나 근거 있음 27건 중 21건에도 지적을 내서 판별력이 없습니다. IA처럼 재검증에서 거절되면 기권하는 규칙을 넣으면 근거 있음 문항의 과유보가 커질 것으로 봅니다. V6의 지시 보강은 이 약점을 줄이지 못했습니다.
